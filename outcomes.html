Program Outcomes

This page shows where I believe the capstone demonstrates each of the five Computer Science program outcomes.

Outcome 1 · Collaboration

Most of the final artifacts were individual projects, so I do not present them as team projects. My collaboration evidence comes from earlier Agile work in CS 250 and from the way I organized the capstone so another person can follow the changes. I kept original and enhanced versions separate, used Git for version control, and documented why the artifact choice changed after the first planning module.

Outcome 2 · Communication

The portfolio itself is part of this outcome. I had to explain the same work in several forms: a code-review script, milestone narratives, before-and-after code examples, and shorter web pages. Other courses also gave me practice changing an explanation depending on the audience, especially the public/admin split in CS 465 and the reporting decisions in DAT 205.

Outcome 3 · Algorithms and Data Structures

The main evidence is the Week 4 enhancement. I kept HashMap for exact-ID operations and added search and filtering methods for cases where an ID is not known. I compared the cost of direct lookup with scanning and sorting the collection and explained why I did not add more indexes to a small in-memory project.

The Weight Tracker also includes a database index for user history. That is a smaller supporting example of choosing a structure around the way the data is actually queried.

Outcome 4 · Techniques, Skills, and Tools

Across the capstone I used Java, Maven, JUnit, Android project structure, XML, SQLite, Gradle files, Git, and GitHub Pages. More important than the list of tools is how they were used. Maven helped organize the CS 320 project, SQLite handled persistent Weight Tracker data, and tests were added around the behavior I changed.

Outcome 5 · Security

The security work is easiest to see in the database artifact. The original Weight Tracker stored passwords in plaintext and did not tie weight rows to an account. The enhanced version hashes passwords, uses account IDs and foreign keys, scopes weight updates and deletes to the current user, adds database constraints, and removes the unused SMS permission.

The CS 320 enhancement also supports this outcome in a smaller way by validating input and preventing callers from directly changing objects stored inside a service.
