Program Outcomes

This page connects the work in my capstone to the five Computer Science program outcomes.

Outcome 1 · Collaboration

Most of the final artifacts are individual projects, so I do not describe them as team projects. For collaboration, I draw from my earlier Agile work in CS 250 and from the way I kept the capstone organized for someone else to review. I kept the original and enhanced projects separate, used Git for version control, and documented the change I made to my original artifact plan.

Outcome 2 · Communication

The portfolio gave me practice explaining the same work in different ways. I wrote a code-review script, milestone narratives, before-and-after explanations, and shorter pages for the website. Earlier courses also gave me practice changing how I explain technical work depending on who will use it.

Outcome 3 · Algorithms and Data Structures

The clearest example is the Week 4 enhancement. I kept HashMap for exact-ID operations and added search and filtering methods for cases where the ID is not known. I compared direct lookup with scanning and sorting the stored records and explained why I did not add more indexing to a small in-memory project.

The Weight Tracker also uses a database index for user history, which is another example of choosing a structure based on how the data is actually searched.

Outcome 4 · Techniques, Skills, and Tools

Across the capstone I worked with Java, Maven, JUnit, Android project files, XML, SQLite, Gradle, Git, and GitHub Pages. I used Maven to organize the CS 320 project, SQLite for the Weight Tracker data, and tests to check the behavior I changed instead of only listing the tools I have used.

Outcome 5 · Security

The database project shows this outcome most clearly. The original Weight Tracker stored passwords in plain text and did not connect weight rows to a user account. The enhanced version hashes passwords, uses account IDs and foreign keys, limits weight changes to the signed-in user, adds database constraints, and removes an unused SMS permission.

The CS 320 work also relates to this outcome because the services validate input and return copies instead of giving outside code the same mutable objects stored inside the service.
