Final evidence synthesis

Five outcomes, traced to specific decisions

The portfolio does not rely on one artifact to prove everything. Each outcome is supported by complementary evidence across the self-assessment, code review, source, narratives, and verification.

Evidence model: the original establishes the starting point; the enhanced source establishes the change; the narrative explains the decision and reflection; the verifier checks the behavior; and the self-assessment connects the work to professional practice.

Outcome 1 · Collaborative environments

Employ strategies for building collaborative environments that enable diverse audiences to support organizational decision-making in the field of computer science.

CS 250 supplied Agile context through user stories, acceptance criteria, sprint review, and retrospective practice. The capstone applies those habits through unchanged baselines, isolated enhancement deltas, decision logs, read-first guides, conventional project structure, traceability maps, and reproducible checks. These strategies let another developer or instructor review one choice without reconstructing the project history.

The work was completed independently, so the portfolio does not misstate it as a production team project. It demonstrates the practices that make later collaboration safer: visible scope, explicit contracts, reviewable evidence, and honest limitations.

Outcome 2 · Professional communication

Design, develop, and deliver professional-quality oral, written, and visual communications that are coherent, technically sound, and appropriately adapted to specific audiences and contexts.

CS 465 required architecture for public travel customers and protected administrators. DAT 205 required scope, privacy, and terminology decisions for donor analysis. Those experiences shaped the portfolio's layered presentation: user problem first, then design decision, source location, test evidence, and limitation.

The public site makes each original and enhanced artifact understandable without requiring a Word download. The narratives provide the full academic analysis. Read-first guides, data dictionaries, complexity documents, diffs, and evidence tables support a technical reviewer. The code-review script supplies the complete oral structure; the recording itself remains the one media dependency to add before final submission.

Outcome 3 · Algorithms and data structures

Design and evaluate computing solutions that solve a given problem using algorithmic principles and computer science practices and standards appropriate to its solution, while managing the trade-offs involved in design choices.

The Category Two artifact separates expected constant-time identifier access from traversal and sorting across map values. Contact, task, and appointment retrieval validates criteria, filters records, copies matches, applies complete comparator chains, and returns immutable lists. Complexity is reported as O(c + n + m log m) time and O(m) result space, with best, selective, and all-match cases.

The database category adds a related but distinct decision: a compound index matches the account-history query, and EXPLAIN QUERY PLAN verifies its use. Alternatives such as tree maps, inverted indexes, date indexes, and extra SQL indexes are evaluated against maintenance, memory, and current access patterns.

Outcome 4 · Computing techniques and tools

Demonstrate an ability to use well-founded and innovative techniques, skills, and tools in computing practices for the purpose of implementing computer solutions that deliver value and accomplish industry-specific goals.

The portfolio uses Java 17, Maven layout, JUnit assets, Android project structure, XML, SQLite, relational constraints, migrations, repositories, cryptographic APIs, Gradle project files, shell and Python verification, diffs, hashes, and GitHub Pages. The value comes from assigning each tool a responsibility rather than from listing technologies.

The service suite protects state and makes failure behavior predictable. The algorithms make retrieval useful and deterministic. The Weight Tracker connects authentication to record ownership, preserves legacy data, and gives the user ordered history and progress. The three focused verifiers record 127 passing checks across these category claims.

Outcome 5 · Security mindset

Develop a security mindset that anticipates adversarial exploits in software architecture and designs to expose potential system vulnerabilities, mitigate design flaws, and ensure privacy and enhanced security of data and resources.

Category One treats mutable aliases, partial updates, invalid input, and ambiguous errors as misuse paths. Category Three begins with specific vulnerabilities: plaintext passwords, no row ownership, registration bypass, unrestricted history, destructive upgrades, weak constraints, unused permission, and backup exposure.

The final code uses centralized validation, defensive copies, specific exceptions, PBKDF2 with unique salts, bounded verifier metadata, randomized inaccessible migration credentials, constant-time comparison, parameter binding, authenticated ownership conditions, foreign-key enforcement, data constraints, migration auditing, disabled backup, and removal of the unused SMS permission. The narrative also records unresolved production risks instead of labeling the classroom app fully secure.
