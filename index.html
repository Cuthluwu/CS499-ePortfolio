Portfolio approach

Traceability before presentation.

Every enhancement is organized as a before-and-after technical review. The unchanged baseline establishes what existed at the start. The enhanced source shows the category-specific work. The narrative explains the design choice, alternative, trade-off, test, result, and remaining limitation.

Module One's initial CS 250 selection remains visible as planning context. The later code review refined the concrete Software Design artifact to the CS 320 service suite because it supports direct source inspection and verification. That decision is documented rather than hidden.

Program outcomes

Claims connected to concrete artifacts.

Full evidence crosswalk →
  1. 01

    Collaborative environments

    Agile context, shared contracts, enhancement maps, decision logs, and reviewable documentation support informed technical discussion without overstating individual work as a full team environment.

  2. 02

    Professional communication

    Narratives, read-first guides, source maps, evidence summaries, and public navigation adapt the same technically precise work for academic and professional review.

  3. 03

    Algorithms and data structures

    Hash-based exact access, value traversals, comparator chains, immutable snapshots, complexity bounds, and indexing alternatives make the implementation trade-offs explicit.

  4. 04

    Computing techniques and tools

    Java, Maven structure, SQLite, repositories, schema constraints, migration, cryptographic password verification, query planning, and repeatable checks deliver specific user and reviewer value.

  5. 05

    Security mindset

    Input boundaries, state isolation, user-scoped queries, parameter binding, foreign keys, credential protection, conservative migration, and explicit limitations anticipate realistic data-integrity and privacy risks.
