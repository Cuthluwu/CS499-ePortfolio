What I reviewed

I looked at what the projects already did, how the classes were organized, how invalid input and missing records were handled, what the tests covered, and what I would change now after taking more computer science courses.

CS 320 service project

The Contact, Task, and Appointment services already met the requirements of the original class. Each service used a HashMap to store records by ID, and the project included JUnit tests for the field rules.

When I reviewed the source again, I noticed that the model classes repeated similar validation checks. The service methods also handled missing records in different ways: a direct getter could return null, while operations that used the private find methods threw a general IllegalArgumentException. The services stored and returned the same mutable objects they were given, so code outside the service could change stored data without using an update method.

The original project also relied on exact IDs. That worked for the assignment, but there was no way to search contacts, tasks, or appointments when the caller did not already know the ID. These observations became the basis for the first two capstone categories.

CS 360 Weight Tracker

The original Weight Tracker could register a user, check a login, and create or change weight records in SQLite. Its database was simple: the users table stored the username and password, and Userdetails stored name, weight, and date.

The main problems were easy to see in DBHelper. Passwords were compared directly as stored text, weight rows had no user ID connecting them to an account, the person's name was the primary key for a weight row, weight and date were text fields, the history query selected every row, and onUpgrade() dropped both tables.

Enhancement plan

  • Software Design and Engineering: organize the Java project, share common validation, return copies instead of stored mutable objects, make missing-record behavior clearer, improve updates, and make appointment-date testing repeatable.
  • Algorithms and Data Structures: add contact last-name search, task keyword search, appointment date-range filtering, predictable sorting, and complexity analysis.
  • Databases: redesign the SQLite tables, connect weight entries to users, improve password storage, migrate old data instead of dropping it, and add user-specific history queries.

Connection to the program outcomes

The review helped me decide which part of the work fit each program outcome. The algorithms work is easiest to see in Category Two, the database project carries most of the security work, and all three categories gave me material to explain through the narratives and final website.
