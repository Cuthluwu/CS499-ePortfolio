Original artifacts reviewed

CS 320 Contact, Task, and Appointment Services

The original Java work satisfies the field-limit and basic CRUD requirements. It uses a HashMap for exact identifier access and includes model and service tests. The review identifies default-package fragmentation, repeated validation, inconsistent missing-record policies, returned mutable references, partial multi-field update risk, dependence on moving system time, and no user-oriented retrieval across records.

This one original supports two distinct enhancement categories. Category One addresses architecture, validation, service contracts, state ownership, and testability. Category Two retains that design and adds search, filtering, ordering, immutability, and complexity analysis.

CS 360 Android Weight Tracker

The original Android application connects Java activities and XML layouts to SQLite and demonstrates registration, login, and weight CRUD. The review finds that passwords are stored as plaintext, weight rows do not have an account foreign key, record identity depends on a name, weight and date are stored as text, the history query returns every row, upgrade deletes tables, cursors are weakly handled, and template tests do not verify the database behavior.

Planned enhancements

  • Software design: reorganize the suite into a Maven project, centralize validation, define a shared repository contract, replace null command behavior with specific policies, protect mutable state, make updates atomic, and inject a controllable clock.
  • Algorithms: preserve map-based exact-ID access; add case-insensitive contact and task retrieval plus inclusive appointment date ranges; sort results explicitly; return immutable snapshots; and document time and space costs.
  • Databases: normalize users and weight entries, add numeric keys and account ownership, store numeric weight and ISO dates, hash passwords, parameterize CRUD, preserve legacy data through migration, add progress queries and a targeted index, and verify the schema.
