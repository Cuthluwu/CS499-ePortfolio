What I reviewed

I looked at both projects for the same basic things: what already worked, how the code was organized, where logic was repeated, how errors were handled, what tests existed, and whether there were obvious security or data problems.

CS 320 service project

The Contact, Task, and Appointment services already met the original course requirements. They used maps for ID-based CRUD and had JUnit tests for the required field rules.

The main weaknesses I found were repeated validation, inconsistent handling of missing records, mutable objects being stored and returned directly, multi-field updates that could partially succeed, and appointment tests that depended on the current system time. I also noticed that there was no useful way to search across records unless the caller already knew the ID.

I split the improvements into two categories. Category One focuses on design and maintainability. Category Two focuses on search, filtering, ordering, and complexity.

CS 360 Weight Tracker

The original Weight Tracker could register a user, log in, and create or change weight records in SQLite. The biggest problems were in the database design. Passwords were stored as plain text, weight rows were not tied to a user account, a name was used as the row identity, weight and date were stored as text, and the upgrade method deleted the existing tables.

Those issues became the plan for the database milestone: redesign the schema, connect measurements to users, improve credential storage, preserve data during an upgrade, and add better history queries.

Enhancement plan

  • Software Design and Engineering: reorganize the Java project, reduce repeated validation, protect stored objects, improve update behavior, and make date testing more reliable.
  • Algorithms and Data Structures: add contact search, task keyword search, appointment date-range filtering, stable ordering, and written complexity analysis.
  • Databases: redesign the SQLite schema, add user ownership, change password storage, preserve old data during migration, and improve history/reporting queries.

Connection to the program outcomes

The code review helped me decide where the five program outcomes would show up in the final portfolio. The strongest connections are algorithms in Category Two, software-development tools across all three categories, security in the database work, and communication through the review, narratives, and final website.
