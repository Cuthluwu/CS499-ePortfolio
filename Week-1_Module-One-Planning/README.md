## Artifact Strategy

| Artifact | Initial role | Final capstone role |
| --- | --- | --- |
| CS 250 SNHU Travel sprint-review and presentation materials | Software Design and Engineering selection | Preserved Agile, requirements, user-story, audience, and stakeholder-planning context |
| CS 320 Contact, Task, and Appointment Service Suite | Algorithms and Data Structures selection | Concrete source artifact for both Category One design work and a separately isolated Category Two cumulative enhancement |
| CS 360 Android Weight Tracker | Database selection | Independent Category Three artifact for schema, persistence, migration, credential, CRUD, query, and verification work |

The refinement matters because it keeps later claims faithful to inspectable source. The portfolio does not present a newly invented travel application as if it were an enhancement of existing CS 250 code. It preserves the useful planning evidence and moves the code-level work to the artifact that can actually support it.

## Package Quality

The current package contains no nested archives, copy-suffix filenames, or duplicate assignment copies. Its Word document uses Times New Roman 12-point text and double spacing throughout, has clean internal document properties, and has been rendered page by page for inspection.
