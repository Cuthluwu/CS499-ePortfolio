# CS 499 Program Outcome Crosswalk

This crosswalk connects the five Computer Science program outcomes to inspectable artifacts. It does not treat a technology name or a broad statement as evidence; each row identifies the implemented behavior, the design reasoning, and the location where a reviewer can verify the claim.

| Program outcome | Concrete portfolio evidence | Primary review locations |
| --- | --- | --- |
| **1. Collaborative environments and decision support** | The Module One plan preserves stakeholder, user-story, and Agile context. The later enhancement maps, repository contracts, consistent service policies, schema documentation, and decision logs create a shared basis for review and future collaboration. The portfolio describes this as progress toward collaboration rather than claiming that an individually completed artifact represents a full team environment. | [Week 1 plan and refinement](Week-1_Module-One-Planning/); Week 3 `docs/`; Week 5 `docs/CAPSTONE_PROGRESS_AND_DECISION_LOG.md` |
| **2. Professional oral, written, and visual communication** | Each narrative explains the original limitation, exact change, rationale, trade-off, verification, and remaining limitation for technical and academic readers. Read-first guides, before/after maps, evidence summaries, and this public navigation layer provide multiple levels of detail without changing the underlying claim. The Week 6 journal adapts database, wireless, accessibility, and behavioral research into a precise product roadmap while separating completed work from proposed work. | Week 3, Week 4, Week 5, and Week 6 DOCX files; each week's `README.md`; each artifact's read-first guide |
| **3. Algorithms and data structures** | The CS 320 suite preserves average-case O(1) exact-ID access with `HashMap`, adds three multi-record retrieval algorithms, establishes deterministic comparator chains, protects results with snapshots and unmodifiable lists, and evaluates time, space, capacity, and indexing alternatives. Database query and index decisions provide supporting trade-off evidence without being presented as a second Category Two artifact. | Week 4 `Validation.searchTerm`, `ContactService.searchByLastName`, `TaskService.searchByKeyword`, `AppointmentService.findByDateRange`; `docs/ALGORITHM_COMPLEXITY_AND_TRADEOFFS.md`; 19-check verifier |
| **4. Well-founded techniques, skills, and tools** | The software enhancement applies Maven organization, shared validation, explicit exceptions, defensive copying, atomic copy-validate-replace updates, `Optional`, `Clock` injection, and repeatable verification. The database enhancement applies a versioned schema, repositories, constraints, parameter binding, migration, PBKDF2 verification, query planning, and repeatable database/Java checks to deliver user-facing value. The Week 6 roadmap evaluates Bluetooth SIG weight data, Android permissions, idempotent import, goal-aware trend logic, and accessible presentation as a coherent next iteration. | Week 3 enhanced source and 26-check verifier; Week 5 enhanced project, schema/data dictionary, enhancement map, 46 database checks, and 30 Java checks; Week 6 technology journal and roadmap |
| **5. Security mindset** | Service boundaries reject invalid input, prevent reference-based mutation, and preserve state after failed updates. The database enhancement replaces plaintext credential storage with salted PBKDF2 verifiers, scopes CRUD by authenticated user ID, enforces foreign keys and constraints, parameterizes user values, audits migration ambiguity, disables backup, and removes an unused sensitive permission. The Bluetooth roadmap extends that mindset to permission timing, explicit pairing, malformed packets, replayed measurements, shared-scale identity, account-scoped devices, deletion controls, and protected identifiers. The narratives also state what is not solved, including rate limiting, recovery, encrypted sensitive-data storage, production-scale identity controls, and physical-device interoperability. | Week 3 validation/copy/update evidence; Week 5 `SECURITY_ANALYSIS.md`, repository source, manifest, migration documentation, and security/validation verifier; Week 6 security and acceptance analysis |
